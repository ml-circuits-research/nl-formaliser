6. Propunere: Spellchecker în Z3 (Layer separat) & Estimare de Încredere

Design & Plauzabilitate Documentul complet de propunere se află și în Markdown la ../spell_checker_z3.md. Această secțiune sintetizează arhitectura în 2 straturi separate și estimatorul simbolic de încredere.

6.1 De ce un layer separat pe intervale de caractere (nu token-cu-token)?

În datele reale (webmeet-dataset) apar 5 familii de erori ortografice: litere lipsă (selct), litere dublate (beeside), transpoziții (atble, rtee), cuvinte lipite fără spațiu (onte, onthe) și spații inserate/deplasate în mijlocul cuvintelor (stando ut → stand out, theb ars → the bars).

Un spellchecker separat în Layer 1 rezolvă aceste erori prin acoperire exactă pe intervale de caractere în Z3 MaxSMT, folosind exclusiv vocabularul lumii active (~5k–10k forme din kb, indexate SymSpell în <50 ms), și transmite către Layer 2 (formalizatorul Z3) tokenii curățați împreună cu offset-urile brute originale — astfel încât sort=table sort_words=atble sau family_words="theb ars" rămân 100% valide la verificatorul de grounding check.mjs! 

Text brut: "make theb ars below 7 teal"
   │
   ▼  LAYER 1 (SymSpell + Z3 MaxSMT pe intervale de caractere, fast-path 0ms când 0 OOV)
      • Scut hard pe nume proprii (Sri, Kyoto, Work 4), citate, cifre, coduri (n1)
      • Operații: KEEP(0), TRANSPOSE/DOUBLE(6), EDIT_1(8), SPLIT(5..11), SHIFT_SPACE(5)
      • Ieșire: Top-K fraze curate + mapare exactă cleanTok → rawSpan
   │
   ▼  LAYER 2 (Formalizatorul Z3 w.request existent)
      • Primește tokenii curați + rawSpan pentru grounding
      • Returnează modelul optim + alternativă Top-2 (margine Δ_sem)
   │
   ▼  ESTIMATOR SIMBOLIC DE ÎNCREDERE (Calibrat pe dev.jsonl)
      • P(corect | x) ∈ [0, 1] + bandă operațională (HIGH / MEDIUM / LOW)

6.2 Estimarea de încredere (Confidence Score)

Z3 furnizează direct 5 semnale matematice transparente (fără „black-box”):

Semnal Cum se calculează Rol diagnostic
1. Acoperire semantică 1 - (unread + uncovered) / contentTokens Orice token aruncat în unread (cost 120) scade puternic încrederea.
2. Energie MaxSMT normalizată totalSoftPenalty(sol1) / contentTokens Separă potrivirile curate pe chei închise de fallback-urile forțate.
3. Marginea Top-1 vs. Top-2 (Δ_sem) cost(sol2) - cost(sol1) via blocking clause Detectează ambiguitatea reală (Δ_sem ≈ 0 ⇒ două interpretări egale!).
4. Cost & margine Layer 1 editCost / chars și Δ_L1 Penalizează corecțiile ortografice agresive sau segmentările ambigue.
5. Semnale check.mjs errors == 0 (hard gate), warnings, raport chei închise vs open-span Orice eroare ⇒ confidence = 0; warning-urile reduc scorul.

6.3 Estimare realistă de plauzabilitate

  • Fezabilitate tehnică: Foarte ridicată (8.5 / 10) — ~400–600 linii .mjs + ~80 linii SMT-LIB2, fără dependențe externe.
  • Latență: ~0–2 ms pe propoziții fără OOV (fast-path: Z3 Layer 1 nu se apelează), 10–50 ms pe propoziții cu typo-uri; +40–100 ms pentru topK=2 (marginea de încredere).
  • Câștig estimat: recuperează ~75–85% din eșecurile cauzate de typo/split/merge, cu un AUROC estimat de 0.80–0.88 pentru separarea formalizărilor corecte de cele greșite.
  • Riscul #1 de prevenit: supra-corectarea numelor proprii sau substantivelor noi (ex. Sri → sir, starbucks) — eliminat prin scut hard pe majuscule non-inițiale, citate, coduri și restricția de a nu re-segmenta perechi de cuvinte deja valide.
