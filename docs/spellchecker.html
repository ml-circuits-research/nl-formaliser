6. Spellchecker Z3 (Layer 1 Independent) & Estimare de Încredere

Layer 1 Implementat & Testat (8/8 teste) Confidence Calibration: Propunere Componenta de normalizare ortografică Z3 este implementată complet separat de formalizator în src/spell/vocab.mjs, src/spell/z3-spell.mjs, CLI bin/spellcheck.mjs și testele dedicate test/spell.test.mjs. Propunerea completă de design & estimator de încredere se află în ../spell_checker_z3.md.

6.1 Componentă independentă, generică (0 dependență de formalizator)

Spellchecker-ul nu importă nimic din formalizator (src/smt/*, src/lattice/*, src/emit/*, src/index.mjs). Logica sa Z3 MaxSMT operează exclusiv pe un vocabular generic { words, highFreqWords, phrases, exactOnlyWords } — fie furnizat direct (ex. un vocabular custom de spreadsheet fără nicio dependență de SOP Lang), fie extras automat din lumile SOP prin adaptorul extractVocabFromKb(kb, { tab }) (~71 ms pentru 11.627 cuvinte și 3.042 fraze cu flexiuni).

În datele reale (webmeet-dataset) rezolvă toate cele 5 familii de zgomot ortografic: litere lipsă (selct → select), litere dublate (beeside → beside), transpoziții (atble → table, rtee → tree), cuvinte lipite fără spațiu (onte / onthe → on the) și spații deplasate în mijlocul cuvintelor (stando ut → stand out, theb ars → the bars, bar ch art → bar chart).

Fiecare token ieșit păstrează offset-urile exacte din textul brut (rawText, rawStart, rawEnd, op, editCost), astfel încât un pipeline viitor Layer 1 → Layer 2 poate ancora exact sort_words=atble sau family_words="theb ars" în check.mjs.

Utilizare CLI & API independentă

# Rulare teste independente spellchecker (8/8 pass)
npm run test:spell

# CLI standalone (cu vocabular extras din SOP worlds, opțional filtrat pe --tab)
node bin/spellcheck.mjs "copy the atble"
node bin/spellcheck.mjs --top 2 "the losing months should stando ut, so make theb ars below 7 teal"
node bin/spellcheck.mjs --tab diagram --json "bar ch art"

# API programatic generic (cu orice vocabular custom, ZERO dependență de SOP Lang!)
import { createSpellChecker } from './src/spell/z3-spell.mjs';
const checker = await createSpellChecker({
  vocab: { words: ['select', 'cell', 'column', 'the', 'in'], highFreqWords: ['the', 'in'], phrases: ['in the'] },
});
const res = await checker.normalise('selct thec ell', { topK: 2 });
// res.cleanText === 'select the cell', res.margin >= 0, res.tokens[i].rawStart/rawEnd

6.2 Estimarea de încredere (Confidence Score)

Z3 furnizează direct 5 semnale matematice transparente (fără „black-box”):

Semnal Cum se calculează Rol diagnostic
1. Acoperire semantică 1 - (unread + uncovered) / contentTokens Orice token aruncat în unread (cost 120) scade puternic încrederea.
2. Energie MaxSMT normalizată totalSoftPenalty(sol1) / contentTokens Separă potrivirile curate pe chei închise de fallback-urile forțate.
3. Marginea Top-1 vs. Top-2 (Δ_sem) cost(sol2) - cost(sol1) via blocking clause Detectează ambiguitatea reală (Δ_sem ≈ 0 ⇒ două interpretări egale!).
4. Cost & margine Layer 1 editCost / chars și Δ_L1 Penalizează corecțiile ortografice agresive sau segmentările ambigue.
5. Semnale check.mjs errors == 0 (hard gate), warnings, raport chei închise vs open-span Orice eroare ⇒ confidence = 0; warning-urile reduc scorul.

6.3 Estimare realistă de plauzabilitate

  • Fezabilitate tehnică: Foarte ridicată (8.5 / 10) — ~400–600 linii .mjs + ~80 linii SMT-LIB2, fără dependențe externe.
  • Latență: ~0–2 ms pe propoziții fără OOV (fast-path: Z3 Layer 1 nu se apelează), 10–50 ms pe propoziții cu typo-uri; +40–100 ms pentru topK=2 (marginea de încredere).
  • Câștig estimat: recuperează ~75–85% din eșecurile cauzate de typo/split/merge, cu un AUROC estimat de 0.80–0.88 pentru separarea formalizărilor corecte de cele greșite.
  • Riscul #1 de prevenit: supra-corectarea numelor proprii sau substantivelor noi (ex. Sri → sir, starbucks) — eliminat prin scut hard pe majuscule non-inițiale, citate, coduri și restricția de a nu re-segmenta perechi de cuvinte deja valide.
